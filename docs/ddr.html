Analisi del Sistema Robot

Introduction

Goal: Costruire un sistema software che comanda un Differential Drive Robot (DDR)

Requirements

Costruire un sistema software che comanda un Differential Drive Robot (DDR) in modo che, partendo dalla posizione iniziale HOME, il robot si sposti lungo il perimetro di una stanza rettangolare vuota. Il DDR si deve fermare quando tornato in HOME.

Il DDR è anche sensibile ai dati rilevati da un Radar. Quando il Radar rileva un 'intruso' a una distanza minore di una distanza prefissata "DMIN":

- se il DDR si sta muovendo , il DDR si ferma fino a che il Radar non rileva più un 'intruso' così vicino
- se il DDR è fermo in HOME, il DDR ruota su sè stesso fino a che un 'intruso' così vicino scompare

Requirement analysis


ROOM -> Dopo un analisi con il committente risulta quindi naturale andare a rappresentare la stanza come una griglia, dove ogni cella sarà un'unità robotica. La stanza viene modellata quindi come una griglia rettangolare di base b e altezza h unità robotiche, dove b >= 1 unità robotica, h >= 1 unità robotica, in modo che il DDR possa muoversi lungo il perimetro senza uscire dai confini.
Nota: Non usiamo i metri ma usiamo unità robotiche per semplificare la modellazione e l'implementazione del sistema.

HOME -> è un area quadrata di 1 unità robotica in grado di contenere il robot. Ovvero è la cella predefinta della griglia, dalla quale partirà il DDR. 

    [# 
        data class RoomConfiguration( // rappresenta la configurazione della stanza
            val width: Double, 
            val height: Double, 
            val cellSideinMt: Double // lunghezza del lato di una cella in metri
        ) {
            val totalWidthinMt: Double = width * cellSideinMt
            val totalHeightinMt: Double = height * cellSideinMt
            val homePoint: PointInGrid = PointInGrid(0, 0)
        }

        data class PointInGrid(val x: Int, val y: Int)
    #]

RADAR -> Il radar è modellato come un QActor. Esso è un'entità proattiva che controlla i dintorni del DDR rilevando la distanza degli intrusi. Questo attore è quindi una rappresentazione del fatto che il DDR è dotato di un sensore che gli permette di rilevare la presenza di intrusi che si trovano ad una distanza inferiore di DMIN. E' necessario formalizzare questi concetti, il radar comunica con il DDR emettendo un evento. 

    QActor Radar context ctxddr {
        [#
            distanza_intruso = 0; // variabile che rappresenta la distanza dell'intruso più vicino rilevato dal radar
            // Assumiamo per semplificità che il radar veda solo davanti a se e non giri.
        #]
        State s0 initial {
            println("$name | attivo") color green
        }
        Goto emitDistance
        
        State emitDistance {
            emit infoRadar : distance(distanza_intruso)
            // Evento: distance(distanza_intruso) che rappresenta la distanza dell'intruso rilevato dal radar.
        } 
    }

DDR -> Dai requisiti si evince che il DDR è proattivo e risponde a comandi di movimento (avanti, indietro, destra, sinistra) e a comandi di stop.
Dopo un confronto con il committente si arriva alla conclusione che il DDR è fornito dal committente stesso ed è inscrivibile in un quadrato di una unità robotica. E' possibile comunicare con il DDR con http su 8090 sincrona oppure websocket su 8091 asincrona a 2 vie.
